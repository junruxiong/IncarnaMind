# Answers are produced by a tool-calling loop, not a fixed pipeline

An Answer is generated by letting the chat model call tools until it is done. The first tool searches the User's Documents, and the sliding-window grouping of Passages lives inside that tool. MCP servers and skills add more tools and are part of version 1, built right after the notebook core.

The old backend used a fixed pipeline: split the question into sub-questions, pick relevant files, search, then answer. We replaced it for two reasons. MCP and skills need a tool loop anyway. And the loop removes two extra model calls, because the model itself decides how many searches to run and what to search for.

## Considered options

**Becoming a general desktop agent like Tencent's WorkBuddy**: rejected. IncarnaMind stays a documents-first notebook. Tools extend what a Question can draw on and do, rather than turning the app into a general computer assistant.

## Consequences

Models that can't call tools (some small local models) instead get a single search using the Question's text, with the results added to the Question context. When there are Blocks above the Question, that model first makes one short call to rewrite the Question into a self-contained search query from them, like the old CLI's condense step but producing one query, so a follow-up such as "what about its limitations?" searches for what "its" means; with nothing above the Question, or if the rewrite fails, the Question's own text is searched.
